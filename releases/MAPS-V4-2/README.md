## V4-1 에서 달라진 것

### 화면을 둘로 나눴다

V3 의 `#secHome` 하나에 히어로와 3패널이 함께 있었다. 이걸 나눈다.

| 화면 | ID | 내용 |
|------|-----|------|
| 첫 화면 | `#secHome` | 배경 영상 + 메인 타이틀 · 태그라인 · 부제 · CTA. **그것만.** |
| 대시보드 | `#secDash` | 다른 섹션과 같은 형식(메뉴명 · 타이틀 · 설명글) + 3패널 |

타이틀은 `생산기술혁신센터 AI Agent 현황` 이다.

`#secDash` 는 처음에 섹션 헤드 여백 규칙
(`#secTop5 .sec-head,#secPlatform .sec-head,#secCommunity .sec-head`)에서 빠져 있어
기본 `margin-bottom:52px` 를 썼다. 그래서 헤드와 3패널 사이가 넓게 벌어지고 등록
버튼이 아래로 밀려 있었다. 이 목록에 `#secDash .sec-head` 를 넣어 다른 섹션과 같은
간격(`clamp(14px,2.4vh,28px)`)으로 맞췄고, `#secDash .home-actions` 에 음수
`margin-top` 을 줘 등록 버튼을 헤드 쪽으로 더 붙였다.

- 진입 경로 3가지 모두 대시보드로 간다: 상단 메뉴 `대시보드` · `AI Agent 둘러보기`
  버튼 · 첫 화면 하단 `SCROLL` 힌트. 네비/푸터 링크와 CTA 의 `href` 를 `#secDash` 로 바꿨다.
- `fitScreens` 대상(`FIT_IDS`)에 `secDash` 를 추가해 3패널이 한 화면에 들어오도록 압축된다.
- **패널 CSS 는 선택자를 넓혔다.** V3 의 규칙이 전부 `#secHome .home-cols` 처럼
  `#secHome` 자손으로 적혀 있어, 패널을 `#secDash` 로 옮기면 스타일이 통째로 빠진다.
  `#secHome` 자손 선택자 75곳을 `:is(#secHome,#secDash)` 로 바꿨다.
  `:is()` 는 인자 중 가장 높은 특이성을 취하므로 `#secHome` 과 특이성이 같다 —
  뒤따르는 규칙들의 우선순위가 흐트러지지 않는다.

### 히어로 배경 영상

`<canvas id="pxNet">` 와 `particleNet` IIFE 를 걷어내고 `<video id="heroVideo">` +
`<div id="heroVeil">` 로 교체했다. 원 소스는
`https://www.lgensol.com/inc/video/video_main01.mp4#t=3,8`.

첫 화면이 히어로 전용이 되어 **영상을 자를 이유가 없다** — 섹션 전체를 그대로 채운다.
(이전 시안에서 3패널을 피하려고 영상 아래쪽을 마스크로 지웠던 것이 "원본이 잘린다"는
지적을 받은 부분이다. 화면을 나누면서 그 처리가 통째로 필요 없어졌다.)

제시된 템플릿에서 달리 한 것:

| 항목 | 템플릿 | V4-2 | 이유 |
|------|--------|------|------|
| 배치 | `z-index:-2` · `100vh` 고정 | `#secHome` 안 · `top:var(--nav-h)` · `z-index:0` | `-2` 는 페이지 배경 뒤로 숨어 보이지 않는다. 헤더가 `fixed` + 최상단 배경 `transparent` 라 `top:0` 이면 메뉴 글자가 영상 위에 얹힌다. |
| 높이 | `min-height` + `translate` | `height:calc(100% - var(--nav-h))` | `<video>` 는 대체 요소라 `height:auto` 면 `top/bottom` 이 아니라 **영상의 고유 종횡비**로 높이를 잡아 섹션 아래가 빈다. |
| 재생 제어 | 항상 재생 | 화면 밖 · 탭 비활성이면 일시정지 | 배경 영상이 계속 디코딩되면 스크롤이 무거워진다. |
| 실패 처리 | 없음 | `error` · 8초 무응답이면 영상·딤 모두 숨김 | 사내망에서 막히면 깨진 영역 대신 기존 그라디언트만 남는다. |
| 딤 | `rgba(0,0,0,.4)` | 그대로 | 아래에 패널이 없으니 세게 덮을 이유가 없다. |

문구는 영상 위에 얹힌다. V3 의 박스형 스크림(`.hero::before`)은 밝은 영상에서
어두운 타원으로 드러나므로 끄고, 글자 자체에 그림자를 준다. 제목은 `text-shadow`
가 아니라 `filter: drop-shadow` 다 — 안의 `<span class="grad">` 가
`background-clip:text` + `-webkit-text-fill-color:transparent` 라 `text-shadow` 는
투명한 글자 속으로 비쳐 지저분해진다.

`SCROLL` 힌트는 `bottom:82px` 다. 하단 고정 검색바(`.dockbar`: `bottom:18px` +
높이 `48px`)를 피해야 해서, 26px 에 두면 정확히 가려진다.

## 사내 클라우드(원격 데스크톱) 성능

원격 데스크톱 계열은 화면을 실시간 인코딩해 전송하므로 비용이
`변하는 픽셀 면적 × 변하는 빈도` 에 비례한다. 전체 화면 배경 영상은 매 프레임
화면 전체가 바뀐다 — 실측(1440×832 표시) **초당 약 73 메가픽셀**. 정지 화면이면
0 에 가깝다. 이것이 로컬과 사내 클라우드의 차이다.

코드에 반영한 것:

| 조치 | 내용 |
|------|------|
| 스크롤 중 일시정지 | 스크롤 시작 시 정지, 멈춘 뒤 0.18초에 재개. 원격 프로토콜이 화면 이동과 영상 변화를 동시에 인코딩하는 최악 구간을 없앤다. 히어로를 보는 동안에는 계속 재생된다 |
| 합성 레이어 고정 | 영상·딤을 각각 독립 레이어로 승격(`translateZ(0)` · `contain:paint`) |
| `preload` | `auto` → `metadata`. 첫 진입에 파일 전체를 끌어오지 않는다 |

**한계**: 위 조치는 스크롤 순간의 부담만 줄인다. 히어로를 보고 있는 동안의 지속
전송량은 줄지 않는다. 그건 **영상을 사내에 두고 720p·24fps 로 재인코딩**해야 해결된다
— 방법은 `docs/사내-공유-및-서버화-가이드.md` 4장 참고. 외부 통신도 함께 0 이 된다.

로컬(Chromium) 측정으로는 적용 전후 프레임 시간에 차이가 없다. 로컬에서는 디코딩이
병목이 아니기 때문이며, 이득은 원격 전송량 쪽에서 나온다. 이 환경에서는 원격 화면
인코더를 재현할 수 없어 수치로 증명하지 못했다.

## 알아 둘 것

영상은 외부 주소를 그대로 참조한다. 파일 안에 담겨 있지 않으므로 인터넷이 없거나
`lgensol.com` 이 막힌 망에서는 폴백 배경이 나온다. 사내 배포 시에는 영상을 사내
서버에 올리고 `<source src>` 를 그 주소로 바꾸는 편이 안전하다.
