# MAPS 온프레미스 서버 구축 절차 — PC 1대 구성

> **전제**: "새 PC 한 대를 서버로 들여와, 로우 데이터도 전부 그 PC 에 두고,
> HTML 을 서버 주소로 공유한다" 로 방향이 정해진 경우의 **실행 절차서**다.
> 다른 선택지(사내 클라우드·기존 웹서버 등)와의 비교는
> [`사내-공유-및-서버화-가이드.md`](./사내-공유-및-서버화-가이드.md) 를 참고한다.

---

## 결론 — 가능하다. 이 앱 규모에 정확히 맞는 구성이다

코드에서 확인한 근거:

- `index.html` 은 **단일 정적 파일**이다. 서버 사이드 렌더링이 없다.
- 동적 기능이 전부 `api/*` 로 분리돼 있다(총 **62개**, 부록 A).
- 파일 업로드가 전부 **base64 JSON POST** 다 — `FormData` 를 쓰지 않는다.
  멀티파트 처리기가 필요 없고, 백엔드는 JSON 하나만 다루면 된다.
- 사용자는 사내 인원, 데이터는 대시보드 목록·게시글·Q&A·첨부 정도.
  **DB 서버를 따로 둘 규모가 아니다 — SQLite 파일 하나로 충분하다.**

PC 한 대에 `정적 파일 + API + DB + 첨부파일` 을 전부 얹는 구성이 과하지도 부족하지도 않다.

---

## 0. 시작 전 반드시 알아야 할 제약 3가지

이걸 모르고 시작하면 나중에 다시 뜯어야 한다. 셋 다 코드에서 확인한 사실이다.

### 제약 1 — HTML 과 API 는 반드시 같은 출처(origin)

코드의 모든 호출이 `fetch("api/…")` · `fetch("data/…")` **상대경로**다.
절대주소 호출은 **0건**이다.

> HTML 을 A 서버에, API 를 B 서버(또는 다른 포트)에 두면 **전부 깨진다.**
> 한 프로세스에서 둘 다 서빙하거나, 리버스 프록시 뒤에서 **하나의 출처**로 묶어야 한다.

"포트만 나누면 되겠지" 가 가장 흔한 실수다. `http://ip` 와 `http://ip:3000` 은
브라우저 입장에서 **다른 출처**다.

### 제약 2 — 서버에는 `index.standalone.html` 을 올리면 안 된다

standalone 사본은 `window.loadShare` · `loadPosts` · `loadLounge` 를 **데모 데이터로
덮어쓴다**. 원본 `index.html` 에는 그 코드가 **0줄**이다.

> standalone 을 서버에 올리면 **백엔드를 다 만들어도 게시판·Q&A·자료공유가
> 영원히 샘플 데이터만 보여준다.** 원인을 찾기 매우 어려운 종류의 문제다.

- 서버에 올릴 것: `releases/MAPS-V4-1/index.html` 또는 `releases/MAPS-V4-2/index.html` (**원본**)
- `index.standalone.html` 은 **"파일로 건네줄 때" 전용**이다

### 제약 3 — 로우 데이터를 한 PC 에 모은다 = 그 PC 가 단일 장애점

디스크가 죽으면 게시글·Q&A·첨부가 전부 사라진다.
**백업은 선택이 아니라 구성 요소다.** 6단계에 포함되어 있다.

## 1. 최종 구성도

```
[사내 임직원 PC / 사내 클라우드]
            │  http://maps.사내도메인
            ▼
┌───────────────────────────────────────────┐
│  MAPS 서버 PC (고정 IP · 24시간 가동)         │
│                                           │
│   웹서버(IIS)  ── /            → 정적 파일    │
│        │        └ /api/*      → 리버스 프록시 │
│        ▼                                  │
│   API 서버(Node.js, localhost:3000)        │
│        │                                  │
│        ├── SQLite   D:\maps\data\maps.db   │
│        └── 첨부파일  D:\maps\files\          │
│                                           │
│   배경 영상  C:\maps\app\hero-720p.mp4      │
└───────────────────────────────────────────┘
            │  매일 새벽 자동 백업
            ▼
    [사내 NAS / 파일서버]
```

핵심은 **웹서버가 정면에 서고 API 는 localhost 뒤에 숨는 것**이다.
이 구조라야 제약 1(같은 출처)이 지켜지고, API 포트가 외부에 노출되지 않는다.

---

## 2. PC 사양

사내 인원 수백 명이 하루에 몇 번 여는 정도의 부하다. **과하게 잡을 필요 없다.**

| 항목 | 권장 | 이유 |
|---|---|---|
| CPU | 4코어 이상 | API 는 가볍다. 여유분 |
| RAM | 16GB | 8GB 로도 되지만 관리가 편하다 |
| 디스크 | SSD 500GB 이상 | 첨부 누적 대비. **데이터용 파티션(D:) 분리 권장** |
| 네트워크 | **유선** 1Gbps | 무선 금지 — 서버는 유선 고정 |
| 전원 | **UPS 권장** | 정전 시 SQLite 파일 손상 방지 |
| OS | Windows 10/11 Pro 또는 Windows Server | 사내 자산·백신·패치 정책이 그대로 적용됨 |

> **Linux(Ubuntu 등)도 가능하다.** 리소스를 덜 쓰고 nginx·Docker·자동백업 구성이
> 더 깔끔하다. 다만 사내 IT 가 리눅스 단말을 자산·보안 정책상 허용하는지 먼저
> 확인해야 한다. 이 문서는 Windows 기준으로 쓰되, 리눅스면 IIS→nginx,
> 작업 스케줄러→cron, nssm→systemd 로 대응된다.

---

## 3. IT 에 신청할 것 — **PC 도입 전에 먼저**

| 항목 | 왜 필요한가 |
|---|---|
| **고정 사설 IP 1개** | DHCP 면 주소가 바뀌어 **공유한 링크가 전부 죽는다.** 가장 중요 |
| 사내 DNS 이름 등록 (`maps.사내도메인`) | IP 를 외우게 하지 않는다. 나중에 서버를 옮겨도 주소가 안 바뀐다 |
| 방화벽 인바운드 80 / 443 | 없으면 **본인 PC 에서만** 열린다 |
| 사내 인증서(HTTPS) | 없으면 브라우저 경고가 뜬다 |
| 자산 등록 · 백신 · OS 패치 | 사내 정책 준수 |
| **24시간 전원 유지 승인** | 절전·자동 종료 정책에서 예외 처리해야 한다 |

### 보안 검토에서 반드시 나오는 질문

**"외부로 나가는 통신이 있는가?"**

2단계(배경 영상 로컬화)를 마치면 **외부 통신 0** 이 된다. 신청서에 이 점을 명시하면
심사가 훨씬 수월하다. 반대로 영상을 외부 주소로 둔 채 신청하면 지적받을 가능성이 높다.

## 4. 설치 순서

### 0단계 — 폴더 구조 확정

```
C:\maps\app\          앱 (교체 대상)
   ├ index.html
   ├ hero-720p.mp4
   └ data\dashboards.json
D:\maps\data\         SQLite DB      ← 앱 교체와 무관
D:\maps\files\        첨부파일 실체    ← 앱 교체와 무관
D:\maps\backup\       백업 임시 폴더
```

**앱과 데이터를 분리하는 것이 핵심이다.** 나중에 화면을 새 버전으로 바꿀 때
`app` 폴더만 교체하면 되고, 실수로 데이터를 날릴 위험이 사라진다.

### 1단계 — 정적만 먼저 띄운다 ★ 여기서 한 번 끊고 검증

1. `제어판 → 프로그램 → Windows 기능 켜기/끄기 → 인터넷 정보 서비스(IIS)` 체크
2. IIS 관리자에서 사이트 물리 경로를 `C:\maps\app` 으로 지정
3. `releases/MAPS-V4-1/index.html`(또는 V4-2)을 `C:\maps\app\index.html` 로 복사
   — **standalone 아님**(제약 2)
4. 방화벽 인바운드 80 허용

**이 시점에 이미 전사 공유가 가능하다.** 대시보드·TOP5·카탈로그·검색·챗봇이 전부 돌고,
게시판·Q&A·로그인만 비어 있다. 여기서 멈추고 **실제 사용자 몇 명에게 링크를 줘서
확인받는 것**을 권한다. 백엔드까지 다 만들고 나서 "화면이 이게 아닌데" 가 나오면 손해가 크다.

### 2단계 — 배경 영상 로컬화 (V4-2 를 쓰는 경우)

외부 통신이 0 이 되고, 사내 클라우드 버벅임도 완화된다.
`ffmpeg` 명령과 상세는 [가이드 4-C](./사내-공유-및-서버화-가이드.md) 참조.

```html
<!-- C:\maps\app\index.html 에서 이 한 줄만 바꾼다 -->
<source src="hero-720p.mp4" type="video/mp4">
```

> 그 영상은 외부 사이트 자산이다. 사내 서버로 복사해 재배포하기 전에 **사용 권한을
> 확인**해야 한다. 필요하면 사내 홍보 영상이나 자체 촬영본으로 교체하는 편이 안전하다.

### 3단계 — `data/dashboards.json` 배치 ★ 비용 0으로 얻는 실데이터

**이건 API 가 아니라 정적 파일이다.** `C:\maps\app\data\dashboards.json` 에 두기만 하면
대시보드 목록이 폴백 샘플이 아닌 **실데이터**로 돈다. 관리자가 파일만 고치면 반영된다.

스키마는 코드의 `FALLBACK` 상수와 같다:

```json
{ "columns": [
    { "team": "新 공정/공법 개발",
      "tag": "New Process & Method Development",
      "items": [
        { "name": "공정 조건 최적화 Agent", "desc": "실험 데이터 기반 최적 조건 탐색",
          "owner": "", "addr": "", "order": 1, "org": "전극기술그룹", "likes": 34 }
      ] }
] }
```

`addr` 가 비어 있으면 **준비중**, 주소가 있으면 **운영중(LIVE)** 으로 표시된다.
`team` 값은 코드의 `ORG_ORDER` 와 정확히 일치해야 정렬이 맞는다.

### 4단계 — API 서버

- **런타임**: Node.js LTS + Express
- **DB**: SQLite (`better-sqlite3`) — 파일 하나. 별도 DB 서버 불필요
- **기동**: `localhost:3000` 에서만 listen (외부 노출 금지)
- **연결**: IIS 의 URL Rewrite + ARR 로 `/api/*` 만 `localhost:3000` 으로 넘긴다
  → **같은 출처 유지**(제약 1)
- **서비스 등록**: `nssm` 또는 `node-windows` 로 Windows 서비스화
  → 재부팅 후 자동 기동. **이걸 빠뜨리면 정전·패치 재부팅 때마다 수동으로 켜야 한다**

구현 범위는 부록 A 를 참고해 단계적으로 나눈다(읽기 → 쓰기 → 관리자).

### 5단계 — 인증

권장 순서:

1. **읽기는 로그인 없이** 공개 — 대시보드·TOP5·카탈로그·공지 읽기
2. **글쓰기·관리자만 로그인** — 게시판·Q&A 작성, 관리자 콘솔
3. 자체 계정으로 시작하되 **사내 SSO(AD/LDAP·SAML·OIDC) 전환을 전제로 설계**한다

현재 코드에는 회원가입 → 관리자 승인 구조가 들어 있다. 빠르게 돌릴 수는 있으나
**비밀번호 보관·초기화 요청·퇴사자 계정 정리가 전부 담당자 업무로 남는다.**
사내 SSO 로 붙이면 그 부담이 사라지고 "누가 썼는지" 감사도 자동으로 남는다.
백엔드 착수 시 **가장 먼저 결정할 항목**이다.

### 6단계 — 백업과 운영

```powershell
# 매일 새벽 3시, 작업 스케줄러에 등록
$d = Get-Date -Format "yyyyMMdd"
Copy-Item D:\maps\data\maps.db "\\NAS\maps\backup\maps_$d.db"
Compress-Archive D:\maps\files "\\NAS\maps\backup\files_$d.zip"
# 30일 지난 백업 정리
Get-ChildItem \\NAS\maps\backup | Where-Object {$_.LastWriteTime -lt (Get-Date).AddDays(-30)} | Remove-Item
```

> **복구를 한 번 실제로 해 본다.** 백업 파일로 다른 PC 에서 서비스를 띄워 보고,
> 게시글이 보이는지 확인한다. **해보지 않은 백업은 백업이 아니다.**

SQLite 는 백업 중 쓰기가 겹치면 파일이 어긋날 수 있다. 안전하게 하려면
`sqlite3 maps.db ".backup 대상경로"` 를 쓰거나, 새벽 트래픽 없는 시간대에 돌린다.

## 5. 데이터 모델 (SQLite 테이블 초안)

코드가 다루는 엔티티에서 도출한 것이다.

| 테이블 | 담는 것 |
|---|---|
| `accounts` | 계정 · 권한(admin/일반) · 승인 상태 |
| `dashboards` | 대시보드 목록(3단계의 JSON 을 DB 로 옮길 때) |
| `posts` · `comments` | 게시판 글 · 댓글 |
| `lounge_posts` · `lounge_replies` | Q&A 스레드 · 답글 |
| `shares` | 자료공유 항목(파일 또는 링크) |
| `dash_requests` | AI Agent 등록 요청 · 승인 상태 |
| `popups` · `manuals` | 팝업 공지 · 매뉴얼 |
| `favorites` · `likes` | 즐겨찾기 · 좋아요 |
| `notifications` | 관리자 알림 |
| `access_log` | `site-visit` · `dash-access` 통계 |

**첨부파일은 DB 에 넣지 않는다.** `D:\maps\files\` 에 저장하고 DB 에는 경로·원본
파일명·크기만 기록한다. DB 가 비대해지면 백업·복구가 급격히 느려진다.

---

## 6. 운영 수칙

- **앱 교체는 `C:\maps\app` 만.** `D:\maps\data` · `D:\maps\files` 는 절대 건드리지 않는다
- 교체 전 이전 `index.html` 을 날짜 폴더로 보관해 롤백 경로를 남긴다
- **담당자 부재 대비** — 설치·백업·복구 절차를 팀 내 최소 2명이 알고 있을 것
- 디스크 사용량을 월 1회 확인 (첨부가 누적된다)

## 7. 자주 막히는 지점

| 증상 | 원인 |
|---|---|
| 본인 PC 에서만 열리고 남들은 접속 안 됨 | 방화벽 인바운드 미허용 |
| 어느 날 갑자기 링크가 전부 죽음 | DHCP 로 IP 가 바뀜 → **고정 IP 필수** |
| 새벽에 서버가 응답 없음 | 절전 모드 진입 → 전원 옵션 "고성능", 절전 해제 |
| 재부팅 후 API 만 죽어 있음 | API 를 서비스로 등록하지 않음 |
| **백엔드를 다 만들었는데 게시판이 계속 샘플만 나옴** | **standalone 파일을 올림 (제약 2)** |
| API 호출이 전부 CORS 오류 | API 를 다른 포트로 분리 (제약 1) |
| 첨부 업로드가 413 오류 | 업로드가 base64 라 원본보다 약 33% 커진다 → 웹서버·API 본문 크기 상한을 넉넉히 |

## 8. 착수 전 결정할 3가지

백엔드 구현을 시작하기 전에 이것부터 정해야 한다.

| 항목 | 선택지 | 영향 |
|---|---|---|
| **OS** | Windows / Linux | 설치 도구 전반 (IIS↔nginx, 작업스케줄러↔cron) |
| **인증** | 자체 계정 / 사내 SSO | 착수 시점과 운영 부담이 크게 갈린다 |
| **1차 범위** | 읽기 전용부터 / 전체 | 읽기 전용은 부록 A 의 약 1/3. 훨씬 빨리 공개 가능 |

## 부록 A. API 엔드포인트 전수 — 총 62개

백엔드 범위 산정·견적에 그대로 쓸 수 있다.
**성격이 셋으로 나뉘며, 구현 방식이 서로 다르다.**

### A-1. JSON API — `fetch` 직접 호출 (50개)

**세션 · 계정 (7)**
`me` · `login` · `logout` · `register` · `accounts` · `pending-accounts` · `approve-account`

**대시보드 · 통계 (9)**
`save` · `dash-stats` · `dash-rank` · `site-stats` · `health` · `health-waive` ·
`favorites` · `popular` · `systems`

**AI Agent 등록 요청 (5)**
`dash-request` · `dash-requests` · `dash-request-cancel` · `approve-dash-request` · `request-status`

**게시판 (7)**
`posts` · `post` · `post-delete` · `post-like` · `comment` · `comment-delete` · `notice`

**Q&A (8)**
`lounge-list` · `lounge-post` · `lounge-edit` · `lounge-delete` · `lounge-like` ·
`lounge-reply` · `lounge-reply-edit` · `lounge-reply-delete`

**자료공유 (2)**
`share-list` · `share-delete`

**관리 · 기타 (12)**
`history` · `html-history` · `upload-html` · `admin-notifications` ·
`manuals` · `manual-save` · `manual-delete` ·
`popup` · `popup-admin` · `popup-save` · `popup-delete` · `popup-dismiss`

### A-2. 파일·이미지 GET — `<img src>` · `<a href>` (7개)

JSON 이 아니라 **바이너리를 그대로 내려주는** 엔드포인트다.
`D:\maps\files\` 에서 읽어 적절한 `Content-Type` 으로 응답해야 한다.

| 엔드포인트 | 용도 |
|---|---|
| `attach?post=&idx=` | 게시글 본문 이미지 |
| `lounge-attach?post=&idx=` | Q&A 첨부 이미지 |
| `share-file?id=&view=` | 자료공유 다운로드 (`view=1` 이면 브라우저에서 바로 열기) |
| `manual?id=` | 매뉴얼 파일 |
| `popup-image?id=` | 팝업 이미지 |
| `html-backup?id=` | 업로드된 HTML 백업본 |
| `req-file?id=` | 등록 요청에 첨부된 HTML |

### A-3. 동적 호출 (5개)

| 엔드포인트 | 특징 |
|---|---|
| `share-add` · `share-edit` | 삼항 연산자로 URL 을 골라 호출 |
| `post-edit` | 동일 |
| `site-visit` · `dash-access` | **`navigator.sendBeacon`** — 응답을 기다리지 않는 통계 전송. 204 로 즉시 끊어도 된다 |

### 정적 파일 (API 아님)

`data/dashboards.json` — 3단계에서 파일로 두면 끝. 서버 구현 불필요.

## 권장 순서 요약

| 순서 | 할 일 | 소요 | 이 시점에 되는 것 |
|---|---|---|---|
| 1 | IT 신청 (고정 IP · DNS · 방화벽 · 전원) | 조직 절차 | — |
| 2 | PC 도입 · 폴더 구조 · IIS 정적 | 반나절 | **전사 공유 시작** (읽기) |
| 3 | 배경 영상 로컬화 | 1시간 | 외부 통신 0 · 버벅임 완화 |
| 4 | `dashboards.json` 배치 | 1시간 | 대시보드 실데이터 |
| 5 | API 서버 (읽기 전용) | 별도 과제 | 공지 · 게시판 읽기 |
| 6 | 인증 + 쓰기 | 별도 과제 | 글쓰기 · Q&A · 관리자 |
| 7 | 백업 자동화 + 복구 훈련 | 반나절 | 운영 안정화 |

**2번까지만 해도 "URL 하나로 전사 공유" 라는 목표는 달성된다.**
파일을 사람마다 전달하며 버전이 갈리는 문제가 그 시점에 사라진다.
