# 지금 쓰는 PC 로 서버 리허설하기

새 PC 를 들여오기 **전에** 지금 PC 로 구성을 미리 시험해 보는 절차다.
새 장비를 받은 뒤 처음 해보는 것보다, 지금 막히는 지점을 미리 겪는 편이 낫다.

전체 구축 절차는 [`온프레미스-서버-구축-절차.md`](./온프레미스-서버-구축-절차.md) 참고.

---

## ⚠ 시작하기 전에 — 회사 정책부터 확인

**개인 업무 PC 에서 포트를 열고 동료에게 공유하는 것이 사내 보안 정책 위반일 수 있다.**
방화벽 인바운드 규칙 추가에 관리자 권한이 필요할 수도 있다.

- **옆자리 1~2명에게 잠깐 보여주는 수준**으로 시작한다
- 부서 전체 공지는 **IT 승인 후**에 한다
- 리허설이 끝나면 서버를 끄고 방화벽 규칙도 되돌린다

리허설의 목적은 "구성이 되는지" 확인이지, 이 PC 로 운영을 시작하는 게 아니다.

## 서버 띄우기

```bash
python3 tools/serve_local.py                          # 최신 릴리스를 8080 으로
python3 tools/serve_local.py --dir releases/MAPS-V4-1 # 버전 지정
python3 tools/serve_local.py --port 9000              # 포트 변경
```

기동하면 **동료에게 전달할 사내 IP URL** 을 직접 찍어 준다.

```
================================================================
  MAPS 리허설 서버  ·  Range(206) 지원
  폴더 : /.../releases/MAPS-V4-2
----------------------------------------------------------------
  내 PC 에서 : http://localhost:8080/
  동료에게   :
               http://10.31.24.87:8080/
```

### `python -m http.server` 를 쓰면 안 되는 이유

파이썬 기본 서버는 **HTTP Range 요청을 지원하지 않는다.** Range 헤더를 보내도
`200 OK` + 전체 본문으로 응답하고 `Accept-Ranges` 헤더도 없다.

V4-2 히어로는 **3초 지점으로 seek** 해서 3~8초 구간만 반복한다.
Range 가 안 되면 그 seek 이 어긋난다. **같은 파일 · 같은 폴더 · 서버만 바꿔** 실측:

| 서버 | Range 응답 | `currentTime` 범위 | 구간 이탈 |
|---|---|---|---|
| `python -m http.server` | `200` (무시) | 0.31 ~ 8.06초 | **6회 — 깨짐** |
| `tools/serve_local.py` | `206 Partial Content` | 3.31 ~ 8.02초 | **0회 — 정상** |

IIS · nginx · Docker nginx 는 Range 를 기본 지원하므로 실제 서버에서는 문제없다.
하필 "가장 간단해서" 제일 먼저 시도하게 되는 파이썬 한 줄만 문제다.

## 리허설 항목 — 이 순서로

### 1. 정적 서빙이 되는가

서버를 띄우고 `http://localhost:8080/` 접속.
대시보드 · TOP5 · 카테고리 그리드 · 차트 · 검색 · 챗봇이 전부 도는지 확인.

> 게시판 · Q&A 가 샘플로 보이면 **정상이다** — standalone 사본을 서빙 중이라는 뜻.
> 백엔드가 없는 지금 단계에서는 그게 맞다(7번 항목 참고).

### 2. 동료가 내 PC 로 접속되는가 ★ 리허설의 핵심

출력된 사내 IP URL 을 **옆자리 사람에게 전달**한다.

- 안 되면 → Windows 방화벽 → 인바운드 규칙 → **TCP 8080 허용**
- 그래도 안 되면 → 사내 네트워크가 단말 간 통신을 막고 있을 수 있다.
  이 경우 개인 PC 로는 불가능하고 **서버망에 있는 장비가 필요하다** —
  새 PC 신청 시 반드시 짚어야 할 항목이다

**이 항목이 통과되면 "URL 하나로 공유" 라는 목표는 기술적으로 검증된 것이다.**

### 3. 영상 구간 반복이 정상인가 (V4-2)

히어로 배경이 **3~8초 구간만 반복**하는지 눈으로 본다.
영상이 처음부터 재생되거나 뚝뚝 끊기면 서버가 Range 를 지원하지 않는 것이다.

### 4. 영상을 로컬로 옮겼을 때 사내 클라우드가 나아지는가

```bash
ffmpeg -ss 3 -t 5 -i video_main01.mp4 \
       -vf "scale=1280:-2,fps=24" -an \
       -c:v libx264 -crf 28 -preset slow -movflags +faststart hero-720p.mp4
```

만든 파일을 `index.html` 옆에 두고 `<source src>` 를 `hero-720p.mp4` 로 바꾼다.
**사내 클라우드에서 접속해 이전과 체감을 비교**한다.

> 원격 데스크톱의 화면 인코더는 개발 환경에서 재현할 수 없다.
> **이 항목만은 실제 사내 클라우드에서 직접 확인해야 한다.**
> 배경은 [가이드 4장](./사내-공유-및-서버화-가이드.md) 참고.

### 5. `data/dashboards.json` 실데이터 전환

서빙 폴더에 `data/dashboards.json` 을 만들어 두고, 대시보드가 폴백 샘플이 아니라
그 파일 내용으로 뜨는지 확인한다. 스키마는
[구축 절차 3단계](./온프레미스-서버-구축-절차.md) 참고.

**API 없이 파일 하나로 실데이터가 된다** — 여기까지가 백엔드 전 단계의 마지막이다.

### 6. 같은 출처 제약을 몸으로 확인 ★ 나중에 가장 크게 물리는 지점

일부러 깨뜨려 보는 것을 권한다.

1. API 스텁을 **다른 포트**(예: 3000)에 띄운다
2. 브라우저 개발자도구 → 콘솔에서 **CORS 오류**를 확인한다
3. 리버스 프록시로 `/api/*` 만 3000 으로 넘겨 **같은 출처**로 만든 뒤 해결되는지 본다

`http://ip:8080` 과 `http://ip:3000` 은 브라우저 입장에서 **다른 출처**다.
"포트만 나누면 되겠지" 가 가장 흔한 실수이고, 실제 구축 때 여기서 막힌다.

### 7. standalone 과 원본의 차이 확인

두 파일을 각각 올려 보고 게시판·Q&A 를 비교한다.

| 파일 | 백엔드 없을 때 | 백엔드 있을 때 |
|---|---|---|
| `index.standalone.html` | 샘플이 채워져 **화면이 온전히 보인다** | **샘플만 계속 보인다 — 함정** |
| `index.html` (원본) | 게시판·Q&A 가 비어 있다 | 정상 동작 |

standalone 은 `window.loadShare` · `loadPosts` · `loadLounge` 를 데모 데이터로
**덮어쓴다**(원본에는 그 코드가 0줄). 백엔드를 붙이는 순간 반드시 원본으로 교체해야 한다.
**이걸 미리 눈으로 봐 두면 나중에 원인 모를 버그로 시간을 버리지 않는다.**

## 지금 PC 로는 검증 못 하는 것 — 새 PC 가 필요한 이유

리허설이 다 통과해도 아래는 확인되지 않는다. 신청 근거로 쓸 수 있다.

| 항목 | 왜 개인 PC 로는 안 되나 |
|---|---|
| **24시간 가동** | 절전·재부팅·패치 재시작 때마다 끊긴다 |
| **고정 IP** | 개인 PC 는 DHCP → 주소가 바뀌면 **공유한 링크가 전부 죽는다** |
| 다수 동시 접속 | 부하 특성을 알 수 없다 |
| NAS 백업·복구 | 백업 경로·권한이 다르다 |
| 서비스 자동 기동 | 수동 실행으로는 검증 의미가 없다 |
| HTTPS · 사내 도메인 | 인증서 발급이 필요하다 |

## 리허설 결과를 신청서에 쓰기

통과한 항목을 그대로 근거로 삼으면 IT 신청이 수월해진다.

> "사내 PC 에서 정적 호스팅으로 시험 구동했고, 동료 접속까지 확인했습니다.
> 정적 HTML 1개 파일이며 서버 사이드 실행이 없습니다.
> 배경 영상을 로컬로 옮겨 **외부 통신은 0건**입니다.
> 운영을 위해 고정 IP · 24시간 전원 · 방화벽 허용이 필요합니다."

특히 **2번(동료 접속)** 과 **4번(영상 로컬화)** 두 가지가 통과되면,
"검증 끝났고 장비만 있으면 된다" 는 상태로 신청할 수 있다.
