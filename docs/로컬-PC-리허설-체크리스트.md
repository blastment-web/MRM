# 지금 쓰는 PC 로 서버 리허설하기

새 PC 를 들여오기 **전에** 지금 PC 로 구성을 미리 시험해 보는 절차다.
새 장비를 받은 뒤 처음 해보는 것보다, 지금 막히는 지점을 미리 겪는 편이 낫다.

전체 구축 절차는 [`온프레미스-서버-구축-절차.md`](./온프레미스-서버-구축-절차.md) 참고.

---

## ⚠ 시작하기 전에 — 회사 정책부터

**개인 업무 PC 에서 포트를 열고 동료에게 공유하는 것이 사내 보안 정책 위반일 수 있다.**
방화벽 인바운드 규칙 추가에 관리자 권한이 필요하다.

- **옆자리 1~2명에게 잠깐 보여주는 수준**으로 시작한다
- 부서 전체 공지는 **IT 승인 후**에 한다
- 리허설이 끝나면 서버를 끄고 방화벽 규칙도 되돌린다

리허설의 목적은 "구성이 되는지" 확인이지, 이 PC 로 운영을 시작하는 게 아니다.

---

## 0. 증상 읽는 법 — 이것부터

브라우저에 이 메시지가 뜬다면:

> **이 페이지에 연결할 수 없습니다 / localhost 연결을 거부했습니다**

이건 **브라우저 문제도 방화벽 문제도 아니다. 서버가 안 떠 있다는 뜻이다.**
"프록시 및 방화벽 점검 중" 같은 브라우저 안내는 무시해도 된다.

확인 순서:

1. 서버를 띄운 **명령창이 아직 열려 있는가?** 닫혔으면 서버도 같이 죽는다
2. 명령창에 **에러 메시지**가 찍혀 있지 않은가? (창이 바로 닫혔다면 에러가 있었던 것)
3. 서버를 아예 안 띄웠는데 브라우저부터 연 것은 아닌가?

**서버가 떠 있으면** 명령창에 이런 배너가 남아 있어야 한다.

```
  내 PC 에서 : http://localhost:8080/
  동료에게   : http://10.31.24.87:8080/
```

## 경로 ★ — 배치 파일로 한 번에 (가장 쉬움)

`tools/rehearsal/` 의 배치·안내와 화면 파일을 폴더 하나에 모아 두면 끝난다.

```
MAPS-실험\
   ├ 선택화면.html          화면을 고르는 첫 페이지 (index- 접두사가 없다)
   ├ index-v4-1.html       →  /v4-1/
   ├ index-v4-2.html       →  /v4-2/
   ├ data\dashboards.json  카드 목록. addr 을 채우면 그 카드가 켜진다
   ├ agents\               올린 자료 (확인용 sample-agent 포함)
   ├ api\maps.ashx         등록요청 백엔드 (접수·1차·2차 승인·카드 생성)
   ├ 1_서버켜기.bat
   ├ 2_서버끄기.bat
   ├ 3_에이전트연결.bat
   └ 읽어보세요.txt
```

**`index-<이름>.html` 하나가 주소 하나다.** 파일을 더 넣고 `1_서버켜기.bat` 을 다시
실행하면 `http://10.x.x.x/<이름>/` 이 생긴다. 배치를 고칠 필요가 없다.

**`1_서버켜기.bat` 를 마우스 우클릭 → `관리자 권한으로 실행`.** 더블클릭은 안 된다.
배치가 아래를 순서대로 하고, 단계마다 OK / 실패를 찍는다.

1. 관리자 권한 확인
2. IIS + **ASP.NET** 기능 켜기 — `dism /online /enable-feature` 를 기능마다 한 번씩
   (ASP.NET 은 등록요청 업로드를 받기 위한 것. .NET Framework 는 Windows 에 이미 있다)
3. `index-*.html` 을 훑어 **파일마다 폴더 하나씩** 배포 + 선택 화면을 루트에 +
   `agents\` 를 루트에 한 벌 + `api\` 를 화면 폴더마다 + `versions.js` 생성 +
   `agents\` 와 **웹 밖의 `maps-data\`** 에만 쓰기 권한(`icacls`)
4. 방화벽 인바운드 TCP 80 허용 (`MAPS-Rehearsal-HTTP-80` 규칙)
5. `w3svc` 기동
6. `curl` 로 **선택 화면과 각 버전 주소**를 스스로 호출해 200 인지 확인하고,
   `ipconfig` 에서 찾은 사내 IP 로 살아 있는 주소를 전부 찍는다

`2_서버끄기.bat` 는 방화벽 규칙 삭제 · 서비스 중지 · 복사한 파일 삭제 · 백업 복원을 한다.
**IIS 기능 자체는 끄지 않는다** — 끄면 재부팅을 요구할 수 있어 오히려 번거롭다.

### 파일 이름이 곧 주소다

```
index-v4-1.html   →   http://10.x.x.x/v4-1/
index-v4-2.html   →   http://10.x.x.x/v4-2/
index-v5.html     →   http://10.x.x.x/v5/      (파일만 넣고 배치 재실행)
http://10.x.x.x/  →   선택 화면 (살아 있는 화면을 카드로 보여준다)
```

배치가 `index-*.html` 을 훑어 파일마다 폴더를 만든다. 버전이 늘어도 배치를 고칠 필요가
없고, 배포하면서 `versions.js` 를 함께 써 두어 **선택 화면에도 카드가 자동으로 늘어난다.**
(새 화면을 넣었는데 선택 화면에 안 보이면 "올렸는데 안 뜬다" 로 또 시간을 버린다)

> 선택 화면 파일 이름이 `선택화면.html` 인 이유가 여기 있다. `index-` 로 시작하면
> 저 규칙에 걸려 선택 화면 자체가 주소로 만들어진다.

폴더 구조는 이렇게 나뉜다.

```
C:\inetpub\wwwroot\
   ├ index.html              선택 화면
   ├ versions.js             배치가 만든 목록
   ├ agents\                 올린 자료 — 화면 버전과 무관하게 한 벌만
   ├ v4-1\index.html + v4-1\data\dashboards.json
   └ v4-2\index.html + v4-2\data\dashboards.json
```

**`agents\` 를 버전 폴더 안에 넣지 않는 것이 핵심이다.** `dashboards.json` 의 `addr` 은
전체 URL(`http://10.x.x.x/agents/foo/`)이라 화면 버전과 무관하게 열린다. 자료가 한 벌이면
모든 버전이 같은 것을 가리키고, 올릴 때도 한 번만 올리면 된다.

앱이 **상대 경로로 읽는 것은 `data/dashboards.json` 하나뿐**이라(루트 절대경로 참조는 0건)
그 파일만 버전 폴더마다 복사한다. 원본은 꾸러미 폴더의 파일 하나이므로 사본이 어긋날 수 없다.

> **오래된 버전을 올려도 된다.** 실제로 V3(팝업 기능이 없는 버전)를 함께 올려 확인했다 —
> 카드는 똑같이 켜지고 자료도 같은 것을 가리키며, 다만 카드를 누르면 팝업 대신
> **새 탭**으로 열린다. 팝업은 V4 부터 들어간 기능이기 때문이다.

> 예전에는 `index.html` 을 갈아 끼우는 방식이라 **"바꿨는데 화면이 그대로"** 가 반복됐다.
> 폴더를 나누면서 그 문제 자체가 사라져 `3_화면바꾸기.bat` 은 없앴다.
> 화면 파일을 고쳐 다시 올릴 때만 `1_서버켜기.bat` 을 한 번 더 실행하고 **Ctrl+F5**.

> **설계상 주의 두 가지.**
> - 사이트 경로를 배치 파일 폴더로 돌리는(`appcmd set vdir`) 대신 **파일을 기본 폴더로
>   복사**한다. 바탕화면·다운로드 폴더는 `IIS_IUSRS` 읽기 권한이 없어 **401.3** 이 나기 쉽다.
> - `dism` 에 `IIS-WebServerRole` 하나만 넘기면 안 된다. `/all` 은 **상위** 기능만 켜므로
>   정적 파일 핸들러(`IIS-StaticContent`)와 기본 문서(`IIS-DefaultDocument`)가 빠진다.

**이 배치 파일은 실행 검증을 하지 못했다.** 이 저장소를 만든 환경은 Linux 라
Windows 명령을 돌려 볼 수 없다. 그래서 로직을 발명하지 않고 표준 명령
(`dism` · `copy` · `netsh` · `net`)만 조합했고, 단계마다 결과를 찍어 **어디서 멈췄는지
바로 보이게** 했다. 막히면 아래 **경로 A** 의 클릭 절차가 같은 결과를 낸다.

**A 를 권한다.** 이유:

- Windows Pro/Enterprise 에 **이미 있다.** 설치 파일도 다운로드도 필요 없다
- **HTTP Range 를 기본 지원**한다 → 영상 구간 반복 문제가 원천적으로 없다
- 서비스로 상주해 재부팅 후에도 자동으로 뜬다
- **새 PC 의 최종 구성도 IIS 다**([구축 절차 4단계](./온프레미스-서버-구축-절차.md)).
  리허설과 실제 구성이 같아져 리허설의 가치가 올라간다

## 경로 A — IIS 를 직접 클릭해서 켜기

> 경로 ★ 의 배치가 멈췄을 때 쓴다. 결과는 같다.
> IIS 는 Windows 10/11 **Home 을 포함해** 모든 에디션의 "Windows 기능" 에 들어 있다.

### A-1. 파일 이름을 `index.html` 로

**IIS 는 `index.html` 을 기본 문서로 찾는다.** `MAPS-V4-1-standalone.html` 이름
그대로 두면 주소 뒤에 파일명을 일일이 붙여야 하고, 기본 문서로도 안 잡힌다.

### A-2. IIS 켜기

1. `제어판` → `프로그램` → **`Windows 기능 켜기/끄기`**
2. **`인터넷 정보 서비스`** 체크 → 확인
3. 설치가 끝날 때까지 기다린다 (1~2분)

**이때 이렇게 보이면 정상**: 브라우저에서 `http://localhost/` 를 열면
IIS 기본 시작 페이지가 나온다.

### A-3. `index.html` 을 기본 폴더에 넣기

`index.html` 을 **`C:\inetpub\wwwroot\`** 안으로 복사한다. 그게 전부다.

> **IIS 관리자에서 사이트 경로를 내 폴더로 돌리는 방법은 권하지 않는다.**
> 바탕화면·다운로드·개인 폴더에는 `IIS_IUSRS` 읽기 권한이 없어 **401.3 (액세스 거부)**
> 가 나기 쉽고, 그때부터는 폴더 권한 편집이라는 곁길로 빠진다.
> 기본 폴더로 복사하면 권한 문제가 아예 생기지 않는다.
> IIS 기본 문서 순서에서 `index.html` 이 `iisstart.htm` 보다 **앞**이라 그대로 우리 화면이 뜬다.

**이때 이렇게 보이면 정상**: `http://localhost/` 에서 **MAPS 화면**이 뜬다.
IIS 기본 페이지가 계속 나오면 파일이 복사되지 않았거나 이름이 `index.html` 이 아닌 것이고,
`403` 이 나오면 기본 문서 기능(`IIS-DefaultDocument`)이 빠진 것이다.

### A-4. 방화벽 열기

1. `Windows Defender 방화벽` → **`고급 설정`**
2. **`인바운드 규칙`** → 오른쪽 `새 규칙`
3. `포트` → `TCP` → **특정 로컬 포트 `80`** → `연결 허용`
4. 프로필은 사내망에 맞는 것만 (보통 `도메인`)
5. 이름은 `MAPS 리허설` 정도로

### A-5. 동료에게 주소 알려주기 ★ 리허설의 핵심

내 IP 확인:

```cmd
ipconfig
```

`IPv4 주소` 를 찾아 `http://10.x.x.x/` 형태로 옆자리에 전달한다.

**이 항목이 통과되면 "URL 하나로 공유" 는 기술적으로 검증된 것이다.**

안 되면:

| 증상 | 원인 |
|---|---|
| 내 PC 에서는 되는데 동료만 안 됨 | 방화벽 (A-4 확인) |
| 방화벽을 열었는데도 안 됨 | **사내 네트워크가 단말 간 통신을 막고 있다** — 개인 PC 로는 불가능하고 **서버망 장비가 필요하다.** 새 PC 신청에 반드시 넣을 항목 |

## 경로 B — Python 을 설치할 수 있다면

`tools/serve_local.py` 를 쓴다. **Windows 에는 `python3` 명령이 없다** —
`py` 또는 `python` 이다.

```cmd
py serve_local.py
```

받은 파일이 스크립트 하나뿐이어도 된다. **같은 폴더에 `index.html` 을 두면**
그 폴더를 서빙한다. 없으면 무엇을 하라는지 알려주는 메시지가 뜬다.

> **`python -m http.server` 는 쓰지 말 것.** HTTP Range 를 지원하지 않아
> V4-2 히어로의 3~8초 구간 반복이 깨진다. 같은 파일로 서버만 바꿔 실측:
> `python -m http.server` 는 `currentTime` 이 0.31~8.06초를 오가며 **구간 이탈 6회**,
> `serve_local.py` 는 3.31~8.02초로 **이탈 0회**.

## 경로 C — 관리자 권한이 없다면

**혼자 확인**은 된다. HTML 파일을 그냥 더블클릭하면 브라우저가 연다.
화면·영상·검색·챗봇 모두 정상 동작한다.

**동료 공유는 어떤 방법으로도 안 된다.** 방화벽을 못 열기 때문이고,
PowerShell 이나 Python 을 써도 마찬가지다.

> **이게 나쁜 소식만은 아니다.** "개인 PC 로는 공유가 불가능하다" 는 사실 자체가
> 새 PC 와 IT 지원이 필요하다는 **가장 명확한 근거**다. 아래 문구를 그대로 쓰면 된다.
>
> "개인 PC 에서 시험한 결과 화면은 정상 동작하나, 방화벽 권한이 없어 동료 공유가
> 불가능합니다. 사내 공개를 위해 서버 장비와 네트워크 설정이 필요합니다."

## 리허설 검증 항목

경로 A 또는 B 로 서버가 떴다면, 이 순서로 확인한다.

| # | 항목 | 이렇게 보이면 정상 |
|---|---|---|
| 1 | 정적 서빙 | `http://localhost/` 에서 MAPS 화면. 대시보드·TOP5·카탈로그·검색·챗봇 동작 |
| 2 | **동료 접속** ★ | 옆자리에서 `http://내IP/` 로 같은 화면 |
| 3 | 영상 구간 반복 (V4-2) | 히어로 배경이 **3~8초 구간만** 반복. 처음부터 재생되면 서버가 Range 미지원 |
| 4 | 영상 로컬화 효과 | 아래 참고 — **사내 클라우드에서 직접 비교해야 한다** |
| 5 | **AI Agent 연결** ★ | 아래 참고 — 올린 HTML 이 카드로 열린다 |
| 6 | **같은 출처 제약** | 아래 참고 — 일부러 깨뜨려 보는 항목 |
| 7 | standalone 함정 | 아래 참고 |

### 3번 — 게시판·Q&A 가 샘플로 보이는 건 정상이다

지금은 백엔드가 없고 **standalone 사본**을 올렸기 때문이다. 그게 맞다.

### 4번 — 영상 로컬화 (사내 클라우드에서만 확인 가능)


### 등록요청 → 1차·2차 승인 → 카드 생성 (백엔드 포함)

`＋ AI Agent 등록` 은 `api/dash-request` 로 POST 하는데 **IIS 는 정적 파일만 주므로**
받아 줄 것이 없어 "서버에 연결할 수 없습니다" 가 떴다. 받는 쪽을 만들었다.

**화면은 이미 2차 승인까지 만들어져 있었다.** 없던 것은 서버뿐이다.

```js
const isSuper = ME.id === "admin";                    // index.html
q.status==="pending"      → isSuper 에게만 [1차 승인] [1차 반려]
q.status==="it_approved"  → isSuper 가 아닌 관리자에게 [2차 승인] [2차 반려]
```

```
pending ──1차(admin)──→ it_approved ──2차(manager)──→ approved → 카드 생성
   └──1차 반려──→ rejected      └──2차 반려──→ rejected
```

**같은 사람이 1차와 2차를 다 할 수 없다.** 화면에서 버튼이 안 보이는 것뿐 아니라
서버에서도 막는다(`1차 검토는 admin 계정만` / `2차 검토는 다른 관리자 계정이`).

#### 저장 위치 — 승인 전 파일과 계정은 웹 밖에 둔다

```
C:\inetpub\maps-data\          ← 웹으로 접근 불가
   accounts.json · sessions.json · requests.json · pending\<id>.html
C:\inetpub\wwwroot\
   agents\<id>\index.html       ← 2차 승인된 것만 여기로 복사된다
   <화면>\data\dashboards.json  ← 2차 승인 시 카드가 추가된다
```

`accounts.json` 을 `wwwroot` 에 두면 `http://IP/data/accounts.json` 으로 그대로 읽힌다.
승인 전 업로드 파일도 마찬가지다. 그래서 밖에 둔다 — **2차 승인 전에는 그 HTML 이
웹에 존재조차 하지 않는다.**

#### 관리자 계정

`1_서버켜기.bat` 이 처음 실행될 때 만든다. 비밀번호는 솔트 + SHA-256 으로 저장한다.

| 단계 | 계정 |
|---|---|
| 1차 | `admin` / `maps2026!` |
| 2차 | `manager` / `maps2026!` |

바꾸려면 `maps-data\accounts.json` 을 지우고 배치를 다시 실행한다.

#### 구현이 둘인 이유

| 파일 | 무엇 | 검증 |
|---|---|---|
| `tools/maps_backend.py` | 참조 구현. 표준 라이브러리만 | **실제 화면으로 전 과정 43개 항목 통과** |
| `tools/rehearsal/api/maps.ashx` | 같은 계약의 IIS 판. 파일 하나 + 내부 라우팅 | **실행 검증 불가** (Windows·.NET 없음) |

둘은 같은 파일 형식을 읽고 쓰므로 서로 바꿔 껴도 된다. 엔드포인트 8종·상태 이름·
카드 필드·요청 항목 필드·상수까지 정적으로 대조해 **전부 일치**를 확인했다.

화면은 `apiFetch` 하나를 통해 나간다 — 있는 그대로 먼저 부르고, 404/405 일 때만
`api/maps.ashx?a=…` 로 재시도한다. `api/*` 호출 56곳을 이 창구로 바꿨다.

#### 작업 중 실측으로 잡은 버그 둘

- **카테고리 문자열 불일치.** 등록 모달 체크박스 값이 `新공정/공법 개발`(붙임)인데
  `ORG_ORDER` 는 `新 공정/공법 개발`(띄움)이라, 승인해도 카드가 엉뚱하게
  `공통 및 루틴 업무` 로 들어갔다. 체크박스 값을 `ORG_ORDER` 와 글자까지 맞췄고,
  서버도 공백을 무시하고 비교하도록 했다
- **새 카드가 안 보였다.** 목록 끝에 붙이면 기본 표시 개수(3개) 밖으로 밀려
  「더보기」에 가린다. `order` 를 최솟값-1 로 주어 맨 앞에 오게 했다

### 원격 화면(사내 클라우드)에서 흐리고 글자가 깨질 때

**브라우저 문제가 아니다.** 원격 데스크톱은 화면을 영상처럼 압축해 전송한다.
계속 움직이는 영역이 크면 인코더가 그 영역에 대역을 다 쓰고 **주변 글자가 손실 압축으로
뭉개진다.** 처음에 흐리다가 점점 선명해지는 것도 같은 이유다(점진적 화질 개선).

와이드에서만 터지는 이유는 산수다. 별자리 배경이 **화면 전체를 매 프레임 다시 칠한다.**

| 해상도 | 프레임당 픽셀 | 60fps 기준 초당 |
|---|---|---|
| 1920×1080 | 2,073,600 | 124 Mpx/s |
| 2560×1080 | 2,764,800 | **166 Mpx/s** (+33%) |
| 2560×1080 · 최적화 켬 | 2,764,800 | **52 Mpx/s** (실측 18.7fps) |

**해결 — 톱니바퀴 → 설정 → "원격 화면 최적화" 켜기.**

- 배경 다시 그리기를 60fps → 20fps (실측 60.0 → 18.7회/초, 166 → 52 Mpx/s)
- `backdrop-filter` 흐림, `.reveal` 등장 애니메이션, 제목 `filter` 를 끈다
  (큰 글자를 `transform` 으로 움직이면 그 구간 동안 텍스트가 레이어로 굳어 뭉개진다)
- **점의 위치·개수는 건드리지 않는다** — 예전 "별자리가 깜빡이며 자리 바뀜" 의 원인은
  강등이 `resize()→seed()` 로 점을 다시 뿌린 것이었다. 이번 스로틀은 `FRAME_MS` 만 바꾼다.
  토글 순간 캔버스 변화량이 평소 120ms(0.188%)보다 오히려 작았다(0.057%) — 재배치 0건

> **자동 감지만 믿으면 안 된다.** 원본 강등은 `requestAnimationFrame` 간격을 재는데
> 원격에서는 이 값이 정상으로 나온다 — 브라우저는 VM 안에서 60fps 로 잘 그리고 있고
> 막히는 곳은 인코더다. 브라우저는 자기 화면이 전송된다는 사실을 모른다.
> 그래서 **스위치가 본체**이고, WebGL 렌더러 이름(SwiftShader·Basic Render·Citrix 등)으로
> 하는 자동 감지는 보조다. 사용자가 끄면 그 선택이 이긴다.

**V4-2 영상이 초반에 느린 것**은 사내 홈페이지에서 받아오기 때문이다.
`preload` 를 `auto` 로 올려 두었고, `<source>` 가 둘이라 **`hero.mp4` 를 화면 폴더에
넣어 두면 코드 수정 없이 로컬 재생으로 바뀐다**(없으면 지금처럼 원격 주소로 폴백).
`1_서버켜기.bat` 은 꾸러미 폴더의 `hero.mp4` 를 각 화면 폴더로 함께 복사한다.
만드는 명령은 아래 4번 항목의 `ffmpeg` 줄과 같다.

### 5번 — AI Agent 연결 (백엔드 없이 된다)

`＋ AI Agent 등록` 버튼은 파일을 `api/dash-request` 로 보내는데, **백엔드가 없으면
그 POST 는 실패한다.** 하지만 연결 자체는 백엔드 없이도 된다. 카드가 켜지는 조건이
데이터 한 줄이기 때문이다.

```js
function isLive(it){ return it.addr && it.addr.trim()!=="" && !it.prep }   // index.html:2453
```

`loadData()` 는 `data/dashboards.json` 을 먼저 찾고 없으면 코드 안 `FALLBACK` 으로
대체한다. 그러니 그 파일을 서버에 놓고 해당 항목의 `addr` 을 채우면 카드가 켜진다.

절차는 `3_에이전트연결.bat` 가 대신한다 — 폴더 이름과 HTML 을 받아
`agents\<폴더>\index.html` 로 올리고, 붙여넣을 `"addr"` 한 줄을 **실제 IP 로 찍어 준 뒤**
메모장으로 `dashboards.json` 을 열고, 닫으면 서버에 반영한다.

꾸러미에는 확인용 예시(`agents\sample-agent`)가 하나 이미 연결돼 있다.
서버를 켜면 **`공정 조건 최적화 Agent` 가 `● 사용 가능`** 으로 떠 있어야 한다.

실측으로 확인한 것 (`serve_local.py` + 헤드리스 Chromium):

| 확인 | 결과 |
|---|---|
| 백엔드 없이 카드가 켜지나 | 켜진다. 카테고리 헤더도 `6개 · 운영 1` 로 바뀐다 |
| `api/health` 가 없으면 "접속장애" 로 뜨나 | **안 뜬다.** 실패가 `catch(e){}` 로 삼켜져 상태가 `"ok"` 로 기본 처리된다 |
| 눌렀을 때 올린 페이지가 열리나 | 열린다 (200) |

> **`addr` 에는 전체 URL 을 넣어야 한다.** `normAddr()`(`index.html:2455`)이 스킴 없는
> 값 앞에 `http://` 를 붙여 `"agents/foo/"` 를 `http://agents/foo/` 로 깨뜨린다.
> 서버 IP 가 바뀌면 등록한 주소가 전부 죽는다는 뜻이기도 하다 — 고정 IP 가 필요한
> 또 하나의 근거다.

### 카드를 누르면 팝업으로 열린다

올린 자료는 새 탭이 아니라 **화면 안 팝업**으로 뜬다. 닫으면 보던 목록·검색어·스크롤이
그대로 남는다. 닫기는 `×` · 배경 클릭 · `ESC` · **브라우저 뒤로가기** 넷 다 된다.

- 팝업 상태의 주소가 `…/#agent=<폴더>` 가 되어, **그 링크를 그대로 보내면 상대 화면에서도
  같은 팝업이 열린 채로 뜬다.**
- 8초가 지나도 안 뜨면 **"새 탭에서 열기"** 가 나타난다. 교차 출처 iframe 은 실패를
  자바스크립트로 감지할 방법이 없어서, 감지하는 척하는 대신 탈출구를 준다.
- **다른 서버 주소는 팝업이 아니라 새 탭 그대로다.** 남의 서버는 대개
  `X-Frame-Options` 로 프레이밍을 거부해 팝업으로 열면 빈 화면이 된다.
  항목에 `"open":"popup"` 을 넣으면 강제할 수 있다.

> **ESC 한 가지 한계** — iframe 안쪽에 포커스가 있으면 부모로 `keydown` 이 오지 않아
> ESC 가 듣지 않는다. 샌드박스라 iframe 문서에 리스너를 심을 수도 없다.
> 그래서 `×` 버튼이 실질적인 닫기 수단이다.

### 보안 — 팝업은 격리해서 띄운다

남이 만든 HTML 을 그냥 같은 출처에서 띄우면 그 페이지가 MAPS 의 DOM·쿠키·`api/*` 에
닿는다. **여러 사람이 올린다는 전제 자체가 이걸 필수로 만든다.**
그래서 `allow-same-origin` 없이 샌드박스로 띄운다. 실측으로 확인했다.

```
parent.document        → 차단됨 (SecurityError)
parent.document.cookie → 차단됨 (SecurityError)
document.cookie        → 차단됨 (SecurityError)
localStorage           → 차단됨 (SecurityError)
window.origin          → null   (불투명 출처)
```

대가가 있다. 그 페이지는 **옆에 둔 파일을 `fetch` 로 못 읽고 `localStorage` 도 못 쓴다.**
자료를 **단일 HTML 파일**로 만들어 달라고 안내해야 하는 이유다.
제약이 걸리는 자료가 생기면, 새 PC 에서 **업로드 영역을 다른 포트의 사이트로 분리**하면
된다. 진짜 다른 출처가 되어 `allow-same-origin` 을 켜도 MAPS 에는 닿지 못한다.

### 6번 — 같은 출처 제약을 몸으로 확인

나중에 백엔드를 붙일 때 **가장 크게 물리는 지점**이다. 미리 겪어 두면 좋다.

`http://내IP` 와 `http://내IP:3000` 은 브라우저 입장에서 **다른 출처**다.
"포트만 나누면 되겠지" 가 가장 흔한 실수다. API 를 다른 포트에 두면
콘솔에 CORS 오류가 뜨고 화면이 비어 버린다.
IIS 의 **URL Rewrite + ARR** 로 `/api/*` 만 넘겨 같은 출처로 묶어야 한다.

### 7번 — standalone 과 원본의 차이

| 파일 | 백엔드 없을 때 | 백엔드 있을 때 |
|---|---|---|
| `index.standalone.html` | 샘플이 채워져 **화면이 온전히 보인다** | **샘플만 계속 보인다 — 함정** |
| `index.html` (원본) | 게시판·Q&A 가 비어 있다 | 정상 동작 |

standalone 은 `window.loadShare` · `loadPosts` · `loadLounge` 를 데모 데이터로
**덮어쓴다**(원본에는 그 코드가 0줄). 백엔드를 붙이는 순간 반드시 원본으로 교체해야 한다.

## 부록 — 왜 PowerShell 스크립트를 드리지 않았나

Python 이 없는 PC 를 위해 PowerShell 정적 서버를 만들 수도 있었다.
그러나 이 저장소를 만든 환경에는 PowerShell 도 .NET 도 없어 **실행 검증을 할 수 없었다.**
검증하지 못한 스크립트를 드리는 것보다, **Windows 에 이미 들어 있고 Range 지원이
보장된 IIS** 를 쓰는 편이 안전하다고 판단했다.
