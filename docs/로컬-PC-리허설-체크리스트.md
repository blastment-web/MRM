# 지금 쓰는 PC 로 서버 리허설하기

새 PC 를 들여오기 **전에** 지금 PC 로 구성을 미리 시험해 보는 절차다.
새 장비를 받은 뒤 처음 해보는 것보다, 지금 막히는 지점을 미리 겪는 편이 낫다.

전체 구축 절차는 [`온프레미스-서버-구축-절차.md`](./온프레미스-서버-구축-절차.md) 참고.

---

## ⚠ 시작하기 전에 — 회사 정책부터

**개인 업무 PC 에서 포트를 열고 동료에게 공유하는 것이 사내 보안 정책 위반일 수 있다.**
방화벽 인바운드 규칙 추가에 관리자 권한이 필요하다.

- **옆자리 1~2명에게 잠깐 보여주는 수준**으로 시작한다
- 부서 전체 공지는 **IT 승인 후**에 한다
- 리허설이 끝나면 서버를 끄고 방화벽 규칙도 되돌린다

리허설의 목적은 "구성이 되는지" 확인이지, 이 PC 로 운영을 시작하는 게 아니다.

---

## 0. 증상 읽는 법 — 이것부터

브라우저에 이 메시지가 뜬다면:

> **이 페이지에 연결할 수 없습니다 / localhost 연결을 거부했습니다**

이건 **브라우저 문제도 방화벽 문제도 아니다. 서버가 안 떠 있다는 뜻이다.**
"프록시 및 방화벽 점검 중" 같은 브라우저 안내는 무시해도 된다.

확인 순서:

1. 서버를 띄운 **명령창이 아직 열려 있는가?** 닫혔으면 서버도 같이 죽는다
2. 명령창에 **에러 메시지**가 찍혀 있지 않은가? (창이 바로 닫혔다면 에러가 있었던 것)
3. 서버를 아예 안 띄웠는데 브라우저부터 연 것은 아닌가?

**서버가 떠 있으면** 명령창에 이런 배너가 남아 있어야 한다.

```
  내 PC 에서 : http://localhost:8080/
  동료에게   : http://10.31.24.87:8080/
```

## 어느 경로로 갈지 고르기

| | 조건 | 경로 |
|---|---|---|
| **A** | 관리자 권한이 있다 | **IIS** (권장) — Windows 에 이미 들어 있다 |
| **B** | Python 을 설치할 수 있다 | `serve_local.py` |
| **C** | 관리자 권한이 없다 | 혼자 보기만 가능 — 그 자체가 신청 근거 |

**A 를 권한다.** 이유:

- Windows Pro/Enterprise 에 **이미 있다.** 설치 파일도 다운로드도 필요 없다
- **HTTP Range 를 기본 지원**한다 → 영상 구간 반복 문제가 원천적으로 없다
- 서비스로 상주해 재부팅 후에도 자동으로 뜬다
- **새 PC 의 최종 구성도 IIS 다**([구축 절차 4단계](./온프레미스-서버-구축-절차.md)).
  리허설과 실제 구성이 같아져 리허설의 가치가 올라간다

## 경로 A — IIS 켜기 (권장)

> Windows **Home** 에디션에는 IIS 가 없다. Pro / Enterprise / Server 에만 있다.
> `설정 → 시스템 → 정보` 에서 에디션을 확인할 수 있다.

### A-1. 파일 준비 — 이름이 중요하다

폴더를 하나 만들고, 받은 HTML 을 **`index.html` 이라는 이름으로** 넣는다.

```
C:\maps\
   └ index.html        ← MAPS-V4-2-standalone.html 의 이름을 바꾼 것
```

**IIS 는 `index.html` 을 기본 문서로 찾는다.** `MAPS-V4-2-standalone.html` 이름
그대로 두면 주소 뒤에 파일명을 일일이 붙여야 하고, 기본 문서로도 안 잡힌다.

### A-2. IIS 켜기

1. `제어판` → `프로그램` → **`Windows 기능 켜기/끄기`**
2. **`인터넷 정보 서비스`** 체크 → 확인
3. 설치가 끝날 때까지 기다린다 (1~2분)

**이때 이렇게 보이면 정상**: 브라우저에서 `http://localhost/` 를 열면
IIS 기본 시작 페이지가 나온다.

### A-3. 사이트 경로를 내 폴더로

1. 시작 메뉴에서 **`IIS 관리자`** 실행
   (안 보이면 `Windows 관리 도구` 안에 있다)
2. 왼쪽 트리에서 `사이트` → **`Default Web Site`** 클릭
3. 오른쪽 `작업` 패널 → **`기본 설정`**
4. `실제 경로` 를 `C:\maps` 로 바꾸고 확인
5. 오른쪽 `작업` → **`다시 시작`**

**이때 이렇게 보이면 정상**: `http://localhost/` 에서 **MAPS 화면**이 뜬다.
IIS 기본 페이지가 계속 나오면 경로가 안 바뀐 것이고,
`403` 이 나오면 폴더에 `index.html` 이 없거나 이름이 다른 것이다.

### A-4. 방화벽 열기

1. `Windows Defender 방화벽` → **`고급 설정`**
2. **`인바운드 규칙`** → 오른쪽 `새 규칙`
3. `포트` → `TCP` → **특정 로컬 포트 `80`** → `연결 허용`
4. 프로필은 사내망에 맞는 것만 (보통 `도메인`)
5. 이름은 `MAPS 리허설` 정도로

### A-5. 동료에게 주소 알려주기 ★ 리허설의 핵심

내 IP 확인:

```cmd
ipconfig
```

`IPv4 주소` 를 찾아 `http://10.x.x.x/` 형태로 옆자리에 전달한다.

**이 항목이 통과되면 "URL 하나로 공유" 는 기술적으로 검증된 것이다.**

안 되면:

| 증상 | 원인 |
|---|---|
| 내 PC 에서는 되는데 동료만 안 됨 | 방화벽 (A-4 확인) |
| 방화벽을 열었는데도 안 됨 | **사내 네트워크가 단말 간 통신을 막고 있다** — 개인 PC 로는 불가능하고 **서버망 장비가 필요하다.** 새 PC 신청에 반드시 넣을 항목 |

## 경로 B — Python 을 설치할 수 있다면

`tools/serve_local.py` 를 쓴다. **Windows 에는 `python3` 명령이 없다** —
`py` 또는 `python` 이다.

```cmd
py serve_local.py
```

받은 파일이 스크립트 하나뿐이어도 된다. **같은 폴더에 `index.html` 을 두면**
그 폴더를 서빙한다. 없으면 무엇을 하라는지 알려주는 메시지가 뜬다.

> **`python -m http.server` 는 쓰지 말 것.** HTTP Range 를 지원하지 않아
> V4-2 히어로의 3~8초 구간 반복이 깨진다. 같은 파일로 서버만 바꿔 실측:
> `python -m http.server` 는 `currentTime` 이 0.31~8.06초를 오가며 **구간 이탈 6회**,
> `serve_local.py` 는 3.31~8.02초로 **이탈 0회**.

## 경로 C — 관리자 권한이 없다면

**혼자 확인**은 된다. HTML 파일을 그냥 더블클릭하면 브라우저가 연다.
화면·영상·검색·챗봇 모두 정상 동작한다.

**동료 공유는 어떤 방법으로도 안 된다.** 방화벽을 못 열기 때문이고,
PowerShell 이나 Python 을 써도 마찬가지다.

> **이게 나쁜 소식만은 아니다.** "개인 PC 로는 공유가 불가능하다" 는 사실 자체가
> 새 PC 와 IT 지원이 필요하다는 **가장 명확한 근거**다. 아래 문구를 그대로 쓰면 된다.
>
> "개인 PC 에서 시험한 결과 화면은 정상 동작하나, 방화벽 권한이 없어 동료 공유가
> 불가능합니다. 사내 공개를 위해 서버 장비와 네트워크 설정이 필요합니다."

## 리허설 검증 항목

경로 A 또는 B 로 서버가 떴다면, 이 순서로 확인한다.

| # | 항목 | 이렇게 보이면 정상 |
|---|---|---|
| 1 | 정적 서빙 | `http://localhost/` 에서 MAPS 화면. 대시보드·TOP5·카탈로그·검색·챗봇 동작 |
| 2 | **동료 접속** ★ | 옆자리에서 `http://내IP/` 로 같은 화면 |
| 3 | 영상 구간 반복 (V4-2) | 히어로 배경이 **3~8초 구간만** 반복. 처음부터 재생되면 서버가 Range 미지원 |
| 4 | 영상 로컬화 효과 | 아래 참고 — **사내 클라우드에서 직접 비교해야 한다** |
| 5 | `dashboards.json` | 폴더에 `data\dashboards.json` 을 두면 대시보드가 폴백이 아닌 실제 값 |
| 6 | **같은 출처 제약** | 아래 참고 — 일부러 깨뜨려 보는 항목 |
| 7 | standalone 함정 | 아래 참고 |

### 3번 — 게시판·Q&A 가 샘플로 보이는 건 정상이다

지금은 백엔드가 없고 **standalone 사본**을 올렸기 때문이다. 그게 맞다.

### 4번 — 영상 로컬화 (사내 클라우드에서만 확인 가능)

```bash
ffmpeg -ss 3 -t 5 -i video_main01.mp4 -vf "scale=1280:-2,fps=24" -an ^
       -c:v libx264 -crf 28 -preset slow -movflags +faststart hero-720p.mp4
```

만든 파일을 `index.html` 옆에 두고 `<source src>` 를 `hero-720p.mp4` 로 바꾼다.

> 원격 데스크톱의 화면 인코더는 개발 환경에서 재현할 수 없다.
> **이 항목만은 실제 사내 클라우드에서 직접 확인해야 한다.**
> 배경은 [가이드 4장](./사내-공유-및-서버화-가이드.md) 참고.

### 6번 — 같은 출처 제약을 몸으로 확인

나중에 백엔드를 붙일 때 **가장 크게 물리는 지점**이다. 미리 겪어 두면 좋다.

`http://내IP` 와 `http://내IP:3000` 은 브라우저 입장에서 **다른 출처**다.
"포트만 나누면 되겠지" 가 가장 흔한 실수다. API 를 다른 포트에 두면
콘솔에 CORS 오류가 뜨고 화면이 비어 버린다.
IIS 의 **URL Rewrite + ARR** 로 `/api/*` 만 넘겨 같은 출처로 묶어야 한다.

### 7번 — standalone 과 원본의 차이

| 파일 | 백엔드 없을 때 | 백엔드 있을 때 |
|---|---|---|
| `index.standalone.html` | 샘플이 채워져 **화면이 온전히 보인다** | **샘플만 계속 보인다 — 함정** |
| `index.html` (원본) | 게시판·Q&A 가 비어 있다 | 정상 동작 |

standalone 은 `window.loadShare` · `loadPosts` · `loadLounge` 를 데모 데이터로
**덮어쓴다**(원본에는 그 코드가 0줄). 백엔드를 붙이는 순간 반드시 원본으로 교체해야 한다.

## 지금 PC 로는 검증 못 하는 것 — 새 PC 가 필요한 이유

| 항목 | 왜 개인 PC 로는 안 되나 |
|---|---|
| **24시간 가동** | 절전·재부팅·패치 재시작 때마다 끊긴다 |
| **고정 IP** | 개인 PC 는 DHCP → 주소가 바뀌면 **공유한 링크가 전부 죽는다** |
| 다수 동시 접속 | 부하 특성을 알 수 없다 |
| NAS 백업·복구 | 백업 경로·권한이 다르다 |
| HTTPS · 사내 도메인 | 인증서 발급이 필요하다 |

## 리허설 결과를 신청서에 쓰기

통과한 항목을 그대로 근거로 삼으면 IT 신청이 수월해진다.

> "사내 PC 에서 IIS 로 시험 구동했고, 동료 접속까지 확인했습니다.
> 정적 HTML 1개 파일이며 서버 사이드 실행이 없습니다.
> 배경 영상을 로컬로 옮겨 **외부 통신은 0건**입니다.
> 운영을 위해 고정 IP · 24시간 전원 · 방화벽 허용이 필요합니다."

특히 **2번(동료 접속)** 과 **4번(영상 로컬화)** 이 통과되면
"검증 끝났고 장비만 있으면 된다" 는 상태로 신청할 수 있다.

## 부록 — 왜 PowerShell 스크립트를 드리지 않았나

Python 이 없는 PC 를 위해 PowerShell 정적 서버를 만들 수도 있었다.
그러나 이 저장소를 만든 환경에는 PowerShell 도 .NET 도 없어 **실행 검증을 할 수 없었다.**
검증하지 못한 스크립트를 드리는 것보다, **Windows 에 이미 들어 있고 Range 지원이
보장된 IIS** 를 쓰는 편이 안전하다고 판단했다.
